一句话：它到底测什么？What does it measure?

EVM-QuestBench 把大模型当作一个链上意图编译器：输入自然语言任务、运行环境和本轮参数，模型生成 unsigned transaction code；平台在 BSC 的本地 fork 上真实执行，再验证交易和链上状态是否满足用户意图。

EVM-QuestBench treats an LLM as an intent compiler for blockchain actions: given a natural-language task, runtime context, and sampled parameters, the model generates unsigned transaction code. The platform executes it on a BSC fork and verifies the resulting transaction and state.

核心判断：正确答案不是“长得像参考代码”，而是“执行后真的把链上世界变成用户想要的样子”。Core idea: correctness is a verified state transition, not a string match against reference code.

The model writes code; the Controller, Runner, Anvil, and Validator turn it into auditable execution evidence.

两个 split，两个能力面Two splits, two capability profiles

Atomic · 62

单步交易题。模型一次调用 API，返回一段 TypeScript；代码内部可以查询链上状态，但最终提交一笔交易。

Single-operation tasks. One model call returns TypeScript; the code may read chain state, but the benchmark evaluates one submitted transaction.

  • BNB / ERC-20 / NFT
  • PancakeSwap / staking / queries
  • receipt + state delta validation

Composite · 45

多步工作流。模型先规划，Controller 再逐 subtask 调用模型；每轮执行后把结果写回下一轮 prompt。

Multi-step workflows. The model plans first, then the Controller calls it per subtask and feeds observations back into the next prompt.

  • planning phase · not counted
  • execution rounds · scored
  • extra rounds incur efficiency decay

一个真实 Atomic 任务One real Atomic task

bnb_transfer_percentage.json

Transfer 15% of my BNB balance

模型必须查询 agent 当前余额、计算 15%、构造一笔 unsigned transaction。Runner 执行后，Validator 检查交易成功、目标地址、金额、gas 和余额变化。

The model must query the agent balance, compute 15%, and construct one unsigned transaction. The Validator checks success, recipient, amount, gas, and balance change.

动态实例，不是固定答案Dynamic instances, not fixed answers

题目定义写在 JSON 中，但每轮会重新选择自然语言模板并填入参数。随机地址、金额、比例和环境部署地址让模型不能只背一份固定交易。

Task definitions live in JSON, while each run samples a template and resolves parameters. Addresses, amounts, percentages, and environment-derived contracts prevent fixed-answer memorization.

评分不是代码相似度Scoring is not code similarity

Atomic 的 0–100 分来自多个结果约束；Composite 还会根据额外执行轮次衰减。

Atomic scores are weighted outcome checks; Composite adds a decay for unnecessary execution rounds.

一次交易可以拿部分分，但只有所有检查都通过，才会被标记为最终通过。代码写得像参考答案，不代表状态一定正确。
A transaction can earn partial credit, but the final pass flag requires all checks to pass. Looking like a reference answer does not guarantee a correct state transition.
